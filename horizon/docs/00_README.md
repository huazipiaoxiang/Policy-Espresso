# HORIZON · 政策雷达 Agent —— 开发文档包

> 一套可直接投喂给编码 Agent（Claude Code / Codex / Cursor）的完整开发资料。
> 本包只做设计，不含实现代码。

## 0. 这是什么

一个面向金融机构（以汇丰为分析主体）的**区域性金融政策监测与影响分析 Agent**：

1. 定期抓取中国香港及大湾区官方/媒体/智库渠道发布的金融相关政策；
2. 用 AI 抽取结构化政策要素，判定其对汇丰各业务线的影响；
3. 强制进入**人工审核台**，审核通过后才对外分发；
4. 支持"政策 2.0"生成式推演（以 CEPA 粤港澳大湾区主题为样例）。

## 2. 怎么用

**方式 A：一次性启动（推荐）**
把 `01_AGENT_PROMPT.md` 全文 + 其余 9 份文档作为附件，一起丢给编码 Agent，说一句：
> 按 01_AGENT_PROMPT.md 执行 Phase 0，产出骨架后停下来等我确认。

**方式 B：分阶段喂**
每次只给当前 Phase 需要的文档，避免上下文过长：
- Phase 0–1（骨架+抓取）→ 01 + 03 + 06
- Phase 2（AI 抽取+分析）→ 01 + 04 + 05
- Phase 3（审核台+前端）→ 01 + 08 + 04
- Phase 4（政策 2.0）→ 01 + 09 + 05
- Phase 5（上云）→ 01 + 10 + 07

**方式 C：给评审看**
只要一份材料时，发 `02_PRD_MVP.md` + `09_ACCEPTANCE_CASES.md`，这两份能讲清"做什么、做到什么程度算成功"。

## 3. 一句话架构

```
定时调度 → 多源抓取(RSS/Sitemap/列表页/PDF) → 归一化+去重+变更检测
   → 分类(是否金融政策) → 结构化抽取(带原文证据) → 外资行差异条款检测
   → 案例/业务图谱检索(RAG) → 影响评分 + 传导链推演 → 预警草稿
   → 人工审核(双签+留痕) → 分发(站内/邮件/IM) → 复盘入库(沉淀为案例)
```

数据库：本地 SQLite → 云端 RDS PostgreSQL(pgvector)
模型：本地 Ollama / 云端阿里云百炼 qwen 系列（同一 `LLMProvider` 接口）
前端：Next.js + Tailwind + shadcn/ui，CURE 风格深色数据面板

## 4. 需要你确认的事（不阻塞开发；第 2 项已定）

1. **CURE 具体指哪个作品**？当前文档按"深碳色数据指挥中心仪表盘"建模（见 08 文件末尾的假设说明）。给我链接或截图，我可替换 Design Token。
2. ~~分析主体范围~~ **✅ 已定**：只做汇丰两个实体——「香港上海汇丰银行有限公司」（香港注册认可机构）与「汇丰银行（中国）有限公司」（内地注册外商独资法人银行）。**恒生银行及其他集团附属公司不纳入分析范围**；若政策原文点名恒生，系统只打 `group_affiliate_mention` 提示，不改变对汇丰实体的判定、不生成对汇丰的预警。
3. 客户暴露数据能否拿到？若不能，MVP 用合成数据先跑通逻辑（文档按此设计）。
4. 是否有彭博/路透/信报等付费源账号？影响 06 文件的 Tier B 覆盖度。
5. 审核人是谁、几级？默认设计为"分析师 + 合规/业务主管"双签。
6. 外发渠道优先级：站内 / 邮件 / 企业微信 / Teams / 飞书？
7. 部署区域：阿里云中国内地地域（数据不出境，但访问香港站点需公网）还是中国香港地域？
8. 政策 2.0 的成果形态：内部备忘录 / 对外建议书 / 行业白皮书？
9. 语种：中文为主、英文原文也要，是否需要双语对照界面？
10. 数据保留期限与合规要求（银行内部通常 7 年留痕）。

## 5. 别做的事（写在最前面，避免返工）

- ❌ 不要先做"全自动发布"。审核是产品的一部分，不是累赘。
- ❌ 不要让模型自由发挥写影响分析。没有原文证据的结论一律禁止输出。
- ❌ 不要把抓取逻辑硬编码进业务代码。抓取必须走可替换的 `SourceAdapter`。
- ❌ 不要在 MVP 阶段引入 Kafka / K8s / 微服务。单机 + 单体 + SQLite 足够。
- ❌ 不要把客户真实数据喂给外部大模型。脱敏或合成。
