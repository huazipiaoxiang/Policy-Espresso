## === PROMPT START ===

### 一、你的角色

你是 HORIZON（政策雷达）项目的资深全栈 + 金融合规产品工程师。项目已上线基础能力（抓取 → AI 分析 → 预处理 → 发布 → 政策库/推荐/跟进中心/原文库/用户管理）。本次任务是在**现有代码上做增量迭代**，不推倒重来、不更换技术栈。

### 二、硬性约束（沿用且必须遵守）

1. 技术栈不变：后端 Python 3.11 + FastAPI + SQLAlchemy 2.x + Alembic + APScheduler；前端 Next.js 14 App Router + TypeScript + Tailwind；SQLite（本地）/ PostgreSQL（云端）同 ORM。
2. AI 必须可插拔，继续走 `LLMProvider`；所有新 AI 结论带 `evidence[]`，反幻觉护栏不放松。
3. 所有状态变更、模型调用、敏感操作写 `audit_log`。
4. **客户数据去敏是硬规则**：任何面向「政策运营专员(processor)」的界面/接口，客户信息必须经去敏，严禁原文暴露（姓名脱敏、账户/金额模糊化、可识别字段打码）。
5. 前端信息密度优先，不做动画堆砌；表头筛选为纯前端或后端参数化，不破坏现有分页。

### 三、需求清单（分模块实现，每模块给出验收标准）

#### 模块 A · 账户体系与多端登录

**A1 修复密码重置不可用**
- 现状：用户管理里的「重置密码」不可用。
- 要求：排查后端重置接口 + 前端触发链路，使管理员可为任意用户重置密码；重置后强制该用户旧 token/会话失效（如 MVP 无 token 则至少清其登录态）。
- 验收：管理员重置某用户密码后，该用户用新密码可登录、旧密码失效。

**A2 用户右上角头像 → profile 浮窗/页面**
- 要求：点击右上角自身按钮弹出 profile 浮窗（或跳转个人页），支持：查看当前账号信息、修改密码（需验旧密码）。
- 验收：普通用户可自助改密，改密后需重新登录。

**A3 同浏览器多标签登录隔离（修复串号）**
- 现状：登录 A 后，同浏览器另一标签登录 B，A 会被同步成 B。
- 根因预判：当前角色/用户名存在 `localStorage`（`horizon-demo-role` / `horizon-username`），`storage` 事件或读取时机导致串号。
- 要求：会话信息改为「按标签页隔离」——优先用 `sessionStorage`，或引入短时效 token + 每个标签页独立会话；登录态不再跨标签页共享。
- 验收：同浏览器两个标签页分别登录不同用户，互不影响；刷新各自仍保持各自身份。

#### 模块 B · 数据保留与清理策略

**B1 政策库 + 政策预处理仅保留近 5 年**
- 要求：`policy` 与 `policy_preprocess` 按发布日期（`published_at`）超过 5 年即自动清理/归档，不进入默认列表。
- 验收：模拟一条 6 年前政策，跑清理任务后被排除（列表不可见、不参与推荐/预处理）。

**B2 原文库超 5 年删 PDF、保留基础信息与链接**
- 要求：`document` 超过 5 年时，删除其 PDF/附件源文件，仅保留元信息 + 原文链接，供搜索命中后跳转。
- 验收：超 5 年文档的存储文件被清除，`documents` 列表仍可见并可搜索，详情页提示「原文源文件已归档，仅保留链接」。

**B3 被标记跟进的政策永久保留**
- 要求：凡被「跟进专员」标记跟进的政策，豁免于 B1 的 5 年清理（永久保留）。
- 验收：标记跟进政策即便日期超 5 年也不被清理。

#### 模块 C · AI 无关政策判定 + 跟进复核

**C1 每日抓取后 AI 判定「完全无影响」**
- 要求：每日抓取分析完成后，AI 自动对每条政策判定是否「对汇丰完全无影响」（复用现有 `irrelevant_cleanup` 的确定性门禁 + AI 复核）。
- 产出：新增「疑似无关」标记；不自动删除。

**C2 跟进中心新增「被标记跟进」区块**
- 要求：在「政策运营专员」的跟进中心里，于「政策使用者发来的影响报告」区块下方新增一块，展示「被标记跟进的政策」清单（即 C1 判定的无影响政策，待人工决定保留/删除）。
- 歧义假设：原需求句子在「再加一个」后缺失，我按「再加一个被标记跟进政策列表区块」实现；若你想加的是别的，请纠正。

**C3 跟进专员决定保留/删除**
- 要求：跟进专员对 C2 清单逐条操作「保留」或「删除」；保留 = 打跟进标记（触发 B3 永久保留），删除 = 走现有 `delete_policy_and_document` 并审计。
- 验收：处理动作可回溯；删除后原文/政策按既有规则清理。

#### 模块 D · 列表表头筛选

- 范围：管理员的「政策数据库、政策预处理、原文库、客户信息、用户管理」五个列表。
- 要求：点击表头提供筛选（排序 + 关键字/枚举过滤），支持多列组合；筛选状态可清除。
- 实现建议：后端已有 `q/status/priority/jurisdiction/theme/scope` 等参数，扩展到这些列表；纯前端可筛的字段（如状态、优先级、市场）用下拉，文本用输入。
- 验收：五个列表均能点表头筛选，刷新后筛选逻辑正确、分页不坏。

#### 模块 E · 业务图谱并入政策数据库

- 要求：将「业务图谱」能力并入「政策数据库」页面（作为 tab 或内嵌视图），导航中移除独立入口（可保留直达路由）。
- 验收：管理员在政策数据库内即可查看/切换业务图谱，原有直达路由仍可用。

#### 模块 F · AI 分析能力改造（含运行时 prompt 改动）

**F1 外资银行差异条款提示语改由 AI 生成**
- 现状文案：「本政策涉及外资银行差异条款，对汇丰的适用存在区别对待，影响需重点关注」。
- 要求：该提示由 AI 依据「是否影响外资银行 / 是否对汇丰适用 / 是否需要关注或特别关注」动态生成，展示在**业务影响**区。
- 产出：新增/修改 `app/ai/prompts/` 下对应 prompt；AI 输出结构化字段（含判定理由 + evidence），前端按字段渲染，不写死文案。
- 验收：对无差异条款政策不再出现该提示；对差异政策按程度给出不同措辞。

**F2 政策预处理三栏改为 AI 联网检索**
- 新三栏：① 汇丰对此政策/话题的反应 ② 类似政策 ③ 市面上实际应用。
- 要求：AI agent 结合「本政策摘要 + 重点话题」联网检索后生成；检索仅限公开信息，不外传客户/内部评分数据。
- 产出：替换现有 `hsbc_response / peer_bank_response / market_applications` 的语义与 prompt；保留证据链接。
- 验收：三栏内容来自检索并带来源，非模板填充。

**F3 政策解读「客户影响」去分数化 + 新增「跟进建议」**
- 现状：显示「业务损失 54 · 业务机会 53 · 声誉风险 100」等数字。
- 要求：不再显示这些分数；改为 AI 分析「该政策对当前用户的具体影响」（结合客户画像）；并**新增一列「跟进建议」**，由 AI agent 分析客户经理如何跟进、让用户在该政策下获利，内容尽量贴合跨境业务（跨境支付/理财通/贸易融资等）。
- 验收：客户影响区为自然语言结论；跟进建议列可执行、贴合跨境场景、带依据。

**F4 客户信息 AI 去敏后给运营专员**
- 要求：政策使用者提交的包含客户数据的反馈/影响报告，在给「政策运营专员」展示前，由 AI agent 做模糊化/去敏（姓名、账号、金额、可识别主体打码或区间化）。
- 验收：processor 界面全程不出现可识别的客户信息；原始数据仅 consumer 自身可见；去敏动作可审计。

### 四、实现顺序建议

1. 先做不依赖 AI 的：A（账户/登录）、D（表头筛选）、E（图谱并入）、B（数据保留）。
2. 再做 AI 流程：C（无关判定+跟进）、F（prompt 改造）。
3. F4 去敏放到最后与 C2 联动，避免半成品泄露。

### 五、验收总则

- `make test` 全绿；新增模块补对应测试。
- 所有新 AI 能力在 `MockProvider`（离线）下可跑通。
- 敏感改动（去敏、权限、删除、清理）有审计与回归测试。
- 每模块完成后给出一句话说明改动了哪些文件与如何自测。
