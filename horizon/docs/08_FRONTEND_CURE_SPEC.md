# 08 · 前端规范（CURE 风格）

## 0. 参考基准与假设

参考对象：CURE 类**数据密集型指挥中心仪表盘**——深碳底色、克制的单一强调色（青色系）、状态色编码、KPI 卡 + 环形进度 + 活动流侧栏、固定左侧导航、无衬线字体、信息密度优先。

> ⚠️ 若你指的 CURE 是另一个站点，把链接/截图给我，只需替换本文 §1 的 Design Token，§3 之后的页面结构与交互不用改。

设计三原则：
1. **一屏一决策**：每个页面只回答一个问题（有什么新政策 / 这条要不要动 / 该谁处理）。
2. **证据可见**：任何结论旁边 1 次点击即可看到原文高亮，不做二级弹窗套娃。
3. **密度优先**：48px 行高、13px 正文、允许信息拥挤；不做大间距的"营销风"。

### 1.2 字体与排版

| Token | 值 |
|---|---|
| `font-sans` | `Inter, "Noto Sans SC", "PingFang SC", system-ui` |
| `font-serif` | `"Source Serif 4", "Noto Serif SC", serif`（仅用于阅读态原文与报告标题） |
| `font-mono` | `"JetBrains Mono", ui-monospace`（文号、金额、指标） |
| 正文 | 13px / 20px，`letter-spacing: .01em`（中文 14px / 22px） |
| 标题 | 20px/28 600（页面）、16px/24 600（卡片）、11px/16 500 字距 .08em 大写（栏目标签） |
| 数字 | `font-variant-numeric: tabular-nums`，KPI 值 32px/36 600 |
| 原文引用 | 15px / 26px，`font-serif`，行宽 ≤68 字符 |

### 1.3 间距与圆角

- 基础 4px；常用 8 / 12 / 16 / 24 / 32
- 卡片圆角 `8px`，按钮 `6px`，徽章 `999px`
- 栅格：12 列，间距 16px，内容区最大宽 1600px，左右留白 24px
- 左导航固定宽 232px（折叠 64px），顶栏高 56px

### 1.4 阴影与层级

深色模式**不用阴影**，用 1px 边框 + 底色差分层；浅色模式可用 `0 1px 2px rgba(0,0,0,.04)`。禁止发光、玻璃拟态、渐变背景。

## 3. 七个页面

### 3.1 雷达总览 `/radar`
回答："今天有什么值得我看的？"

```
┌─ KPI 条（4 卡，等宽）─────────────────────────────────────────────┐
│ 今日新增 18      待审 12        P0/P1 3        平均响应 22min     │
│ ↑ +6 vs 昨日     3 项超 SLA     ↑ 1            目标 ≤30min        │
├─ 主区（左 8 列）────────────────┬─ 侧栏（4 列）───────────────────┤
│ 政策流（按优先级排序的紧凑列表）│ 待审队列（Top 5，可点进）        │
│ ┌────────────────────────────┐ │ ┌────────────────────────────┐ │
│ │● P0 广东贴息仅限内资行      │ │ │ 广东省贴息 · 剩余 3h12m    │ │
│ │  省财政厅 · 2h前 · CMB      │ │ │ 金管局通告 · 剩余 5h       │ │
│ │  [外资行被排除] [P0]        │ │ └────────────────────────────┘ │
│ └────────────────────────────┘ │ 业务线影响分布（横向条形）      │
│  ...（虚拟滚动，48px/行）      │ CMB ███████ 6  GBM ███ 3 ...    │
│                                │ 数据源健康（3 红 2 黄）         │
└────────────────────────────────┴─────────────────────────────────┘
```
- 行内左侧 3px 竖条 = 优先级色；行内标签最多 3 个，超出显示 `+2`。
- 支持 `j/k` 上下移动、`Enter` 打开、`r` 标记已读。
- 空状态："暂无新增。最近一次抓取 12:30，12 个源全部正常。"

### 3.2 政策详情 `/policies/[id]`
回答："这条政策到底说了什么，对我什么影响？"

三栏（可拖拽宽度）：
```
┌─ 左：原文（40%）────────┬─ 中：结构化（35%）──────┬─ 右：影响（25%）────┐
│ 标题 / 发文机关 / 文号   │ 适用主体  [被排除] ⚠️    │ 综合分 86.5  P0     │
│ 发布日期 · 生效日期      │  → 引原文句（高亮）      │ 雷达图（8 维）      │
│                          │ 生效日 2026-11-01       │ 方向 利空           │
│ <正文，点击结论即高亮>   │ 金额 最高 500 万元       │ 传导链（4 步箭头）  │
│  ▓▓▓ 政策适用对象为...   │ 义务 3 项（可展开）      │ 影响对象            │
│                          │ 激励 1 项               │ 暴露区间 8–15 亿    │
│ 版本 v3  [查看变更]      │ 主题 #贷款贴息 #大湾区   │ 建议动作 2 条       │
│ [下载 PDF] [原文链接]    │ 置信度 0.86             │ 相似案例 1 条       │
└──────────────────────────┴─────────────────────────┴─────────────────────┘
底部固定操作条：[标记误报] [退回补充] [提交审核]（主按钮）
```
- 证据联动：点击中间栏任一字段 → 左栏滚动并高亮对应 span（黄色底 2s 渐隐）；反向点击原文任一句 → 显示"该句支撑了哪些结论"。
- 右栏评分用 ECharts 雷达图，8 轴，缺值轴留空并灰显。
- "外资行被排除"用 `--p0` 徽章 + 三角形警示，不可仅用颜色区分（加图标 + 文字）。

### 3.3 审核台 `/review`
回答："这条能不能发？"

- 布局：左列表（280px）+ 右详情（剩余）。列表按 SLA 剩余时间升序，超时行标红。
- 详情顶部：`剩余 3h12m` 倒计时 + 当前状态 + 上一审核人意见。
- 三个固定动作按钮：`通过`（主）/`驳回`（次，需选原因码）/`退回补充`（次）。
- 右侧常驻"AI 质疑"面板（P7 链路的输出），列出 3 条最可能出错处 —— 这是防"橡皮图章"的关键设计。
- 驳回原因码：证据不足 / 影响误判 / 适用性误判 / 表述不当 / 重复 / 其他（必填备注）。
- 字段级 diff：审核中途修改任何字段，以 `旧值 → 新值` 形式记录并在提交时二次确认。
- 批量：列表支持多选，仅允许批量"通过 P3"与批量"标记重复"。

### 3.4 案例库 `/cases`
- 顶部搜索框（语义 + 关键词混合），示例提示："外资行被排除的贴息政策"。
- 卡片：标题 / 年份 / 地区 / 主题标签 / 一句话影响 / 结果（我赢了/我输了/部分改善）。
- 详情：时间轴（政策出台 → 我方反应 → 结果 → 后续修订），"启示"单列为引用块。
- 关键：每条案例必须能链到当时的政策原文，否则不算合格数据。

### 3.5 业务图谱 `/business-map`
- 矩阵热力图：行 = 业务线（CMB / GBM / WPB / Markets / GTB / Insurance / PB），列 = 16 个政策主题，格值 = 近 12 个月相关政策数与平均影响分。
- 格子点击 → 抽屉列出该交叉点的政策清单。
- 右侧：Top 5 高敏感主题趋势折线（月度）。
- 用途：给业务主管看"我的板块最近被什么政策冲击最频繁"。

### 3.6 政策 2.0 工作台 `/studio`
- 三栏：左 = 主题树（跨境支付 / 人民币国际化 / 保险 / 专业资格…）；中 = 条款演化时间轴（2003 CEPA → 补充协议 → 服务贸易协议 → 大湾区措施）；右 = 建议书编辑区。
- 生成后每条建议是一张卡：`现行依据`（可展开原文）、`不冲突论证`、`拟条文`、`影响`、`风险`、`KPI`。
- 边界校验结果用三种状态条：`pass` 绿 / `warn` 黄（需立法程序）/ `fail` 红（与现行规定冲突，禁止外发）。
- 顶部常驻声明条："AI 辅助生成，仅供内部研讨，未经政策与合规审核不得对外。"

### 3.7 数据源与任务 `/sources`
- 表格：源名称 / 层级 / 适配器 / 最近成功 / 成功率 7d / 24h 新增 / 状态（绿黄红）/ 操作（立即抓取、停用、编辑）。
- 顶部：总成功率、熔断源数、今日失败任务数。
- 失败详情抽屉：错误类型、堆栈摘要、最近 5 次结果、建议动作（"疑似改版，检查选择器"）。

## 5. 交互规范

- 快捷键：`⌘K` 全局搜索、`j/k` 列表移动、`Enter` 打开、`a` 通过、`x` 驳回、`?` 快捷键帮助。
- 加载：骨架屏（不用 spinner），列表骨架 6 行。
- 错误：Toast 只用于成功提示；错误用行内 red banner + 重试按钮，可复制的错误码。
- 乐观更新仅用于"标记已读"，审核动作一律等服务端确认。
- 长任务（抓取/生成）：显示进度条 + 可离开页面（后台继续），完成后顶栏红点。
- 国际化：中英切换；数字与日期用 `Intl`，时区固定 `Asia/Hong_Kong`。
- 无障碍：对比度 ≥4.5:1，优先级不只靠颜色，键盘可完成全部审核动作，焦点环 2px `--accent`。

## 6. 技术实现

- Next.js 14 App Router，服务端组件优先，交互组件才 `"use client"`。
- 数据：TanStack Query，`staleTime: 30s`；SSE 订阅 `stream/events` 更新列表与徽章。
- 图表：ECharts（雷达、热力、折线），按需引入，统一在 `lib/charts.ts` 注册主题（跟随 `--accent`）。
- 表格：TanStack Table + 虚拟滚动（`@tanstack/react-virtual`）。
- 样式：Tailwind + CSS 变量（Token 定义在 `globals.css`，`dark` 用 class 切换）。
- 禁止：不要引入 Ant Design/MUI 大包（与 CURE 风格冲突且体积大）。

## 7. 视觉验收清单

- [ ] 1440×900 下，雷达页首屏可见 ≥8 条政策且无需横向滚动
- [ ] 政策详情页三栏在 1280 宽下自动折叠为"原文 / 其他"两 Tab
- [ ] 深色/浅色切换后，所有文本对比度达标，图表颜色同步
- [ ] 优先级、适用范围状态在灰度打印下仍可区分（形状/文字差异）
- [ ] 任意结论 → 原文高亮 ≤1 次点击
- [ ] 审核台键盘可完成：选中 → 阅读 → 通过
