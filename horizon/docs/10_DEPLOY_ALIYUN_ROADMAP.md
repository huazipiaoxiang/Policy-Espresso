# 10 · 上云路径、排期与风险

## 1. 本地 → 阿里云的迁移原则

**一句话**：上云只换"配置与实现"，不改"业务逻辑与数据模型"。

| 层 | 本地 | 云端 | 是否改代码 |
|---|---|---|---|
| 数据库 | SQLite 文件 | RDS PostgreSQL + pgvector | 否（同一 ORM；向量查询用 repository 抽象） |
| 模型 | Ollama / Mock | 百炼 DashScope（OpenAI 兼容端点） | 否（换 `LLM_PROVIDER`） |
| 嵌入 | bge-m3 本地 | `text-embedding-v4` | 否（换 `EmbeddingProvider`） |
| 文件 | 本地卷 | OSS | 否（换 `Storage` 实现） |
| 调度 | APScheduler 进程内 | 保留 + 可选 FC 定时触发器 | 否 |
| 日志 | 文件 | SLS | 否（换 handler） |
| 密钥 | `.env` | KMS / 环境变量注入 | 否 |
| 部署 | docker compose | ECS + docker compose | 否 |

## 2. 目标架构（阿里云）

```
                    ┌── 仅办公网/VPN 访问 ──┐
Internet ── WAF? ── SLB/EIP ── ECS (2c4g, docker compose)
                                  │  ├─ api (uvicorn :8000)
                                  │  └─ web (next :3000)
                                  ├── RDS PostgreSQL 15 + pgvector
                                  ├── OSS（原文快照/PDF/导出）
                                  ├── SLS（日志）
                                  └── 百炼 DashScope（模型/嵌入）
出网：NAT/EIP → 抓取中国香港及内地政府站点
定时：ECS cron 或 函数计算 FC 定时触发 /internal/jobs/crawl（带签名）
```

- **不放在公网裸奔**：安全组只开 443（给 web），8000 只允许内网；管理后台加 IP 白名单。
- **认证**：MVP 单 Key；上线前换 OIDC/企业 SSO（汇丰内部应有 IdP），接口不变。
- **地域选择**：优先中国内地地域（数据留存、等保合规容易过），出网抓取靠公网；若抓取稳定性极差，再考虑中国香港节点只做"抓取+回传纯文本"，并做数据出境评估。

## 3. 迁移步骤（半天可完成）

1. `pg_dump` 不适用（SQLite）→ 用 `alembic upgrade head` 在 RDS 建表，跑一次 `scripts/migrate_sqlite_to_pg.py`（逐表 upsert，向量列重算）。
2. OSS 建 bucket（私有读 + 预签名 URL），跑 `scripts/upload_snapshots.py`。
3. 配 `.env.prod`：`LLM_PROVIDER=dashscope`、`DASHSCOPE_API_KEY`、`DATABASE_URL`、`OSS_*`。
4. 拉起 compose，跑 `/healthz`，跑 Phase 1–3 验收脚本。
5. 切换 DNS/入口，本地环境保留为"演练与降级环境"。

**回滚**：保留本地 SQLite 快照 + 上一版镜像 tag，30 分钟内可切回。

## 4. 成本估算（量级参考，需按实际报价核对）

| 项 | 规格 | 月成本（元，估算） |
|---|---|---|
| ECS | 2 vCPU / 4 GiB / 40G SSD | 100–250 |
| RDS PostgreSQL | 1c2g 基础版 / 50G | 200–400 |
| OSS + 流量 | 50G + 少量外网 | 10–30 |
| SLS | 5G 日志 | 10–30 |
| 百炼（模型） | 50 篇/日，分层调用 | 150–450 |
| EIP/带宽 | 5 Mbps | 50–100 |
| **合计** | | **约 500–1200 / 月** |

省钱手段：夜间批处理、flash 打标、缓存命中、只对 P1+ 用 max 模型。

## 5. 排期（单人全职，含缓冲）

| 周 | 内容 | 交付 |
|---|---|---|
| W1 | Phase 0 骨架 + Phase 1 前 3 个源 | 能跑能看，抓取跑通 |
| W2 | Phase 1 全部源 + 变更检测 + 去重；Phase 2 分类/抽取 | 50+ 文档入库，抽取准确率初测 |
| W3 | Phase 2 适用范围判定 + 影响分析 + 证据校验 | 用例 1 端到端跑通（未审核版） |
| W4 | Phase 3 审核台 + 分发 + 审计 | 双签可跑，审计可查 |
| W5 | Phase 4 案例库 + 政策 2.0 工作台 | 用例 2 生成首版建议书 |
| W6 | 评测集回归 + 修缺陷 + Phase 5 上云 | 验收报告 + 云端环境 |

两人并行（1 后端 + 1 前端/AI）可压到 3–4 周，前提是 Phase 2 的 prompt 与评测集在 W1 就并行准备。

## 8. 上线前检查清单

**功能**
- [ ] 用例 1、用例 2 验收全通过，报告归档
- [ ] 未审核内容分发被 409 拦截（有测试用例）
- [ ] 驳回后可重开，且旧评估被清理
- [ ] 数据源健康页能真实反映故障

**质量**
- [ ] 200 条评测集回归无退化
- [ ] 无证据结论率 = 0
- [ ] 注入攻击成功率 = 0

**安全**
- [ ] 密钥不在代码/镜像/日志中
- [ ] 管理接口 IP 白名单或 SSO
- [ ] 抓取内容全程标记 untrusted，前端不渲染模型 HTML
- [ ] 审计日志不可篡改（只追加），保留 ≥7 年（按行内要求）

**运维**
- [ ] 每日自动备份 + 每月恢复演练一次
- [ ] 关键告警接入（抓取失败、模型报错、磁盘、证书到期）
- [ ] 有降级预案：模型不可用 → 规则模式；向量不可用 → 关键词

## 9. 上云之后（第二期建议）

1. **接内部数据仓**：把客户敞口从合成换成真实（脱敏聚合），影响金额才可信。
2. **定向推送**：按业务线/地区把预警推给对应客户经理（需权限模型）。
3. **政策问答**：基于同一语料做"问政策"（RAG 问答），比看卡片更快。
4. **英文/繁体双语产出**：香港总部与内地团队共用一套结论。
5. **效果回测**：把每次预警的"事后是否发生"记下来，持续校准评分卡权重——这是让系统越用越准的唯一办法。
